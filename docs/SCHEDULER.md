> 原实现：`b4.v.T0(MemoryCard, Rating, long)`（`decompiled/b4/v.java` 约 1175 行）
> 可读重写：`project/app/src/main/java/com/luoyu/aibinhaosi/recovered/scheduler/EbbinghausScheduler.kt`
> 逐语句镜像：`scripts/scheduler_oracle.py`

## 1. 常量

| 常量 | 值 | 出处 |
|---|---|---|
| 固定阶梯 | `[1, 3, 7, 15, 30, 60]` 天 | `b4.v.f931a` |
| 难度因子初值 | `2.35` | `cards.ease_factor DEFAULT 2.35` |
| 难度因子下限 | `1.3` | `AGAIN` 分支的 `max` |
| 难度因子上限 | `3.2` | `EASY` 分支的 `min` |
| 最小到期间隔 | `60_000 ms` | 最后的 clamp |

## 2. 四个分支

### AGAIN（重来，ordinal 0）

```java
long dueAt = now + 60_000;
double ease = max(1.3, prevEase - 0.2);
intervalDays = 60_000 / 86_400_000;   // ≈ 0.000694
repetitions = 0;                       // 归零，明天从阶梯头再来
lapses += 1;
label = "1 分钟";
```

**语义**：彻底忘了。间隔压到 1 分钟（同一会话里马上再出现），但 `repetitions`
归零意味着下一次「记住」会重新从 1 天开始——这是它比标准 SM-2 更激进的地方
（SM-2 的 lapse 通常保留部分 interval）。

### HARD（困难，ordinal 1）

```java
double interval = (reps > 0 && prev >= 1.0) ? max(1.0, prev * 1.2) : 1.0;
double ease = max(1.3, prevEase - 0.15);
repetitions = max(1, reps);            // 不推进
```

**语义**：想起来了但很费力。只把间隔乘 1.2，**不推进阶梯**，难度因子 −0.15。
新卡（reps=0）直接给 1 天。

### GOOD（记住，ordinal 2）

```java
double interval = reps < 6 ? LADDER[max(0, reps)] : max(1.0, prev * ease);
repetitions = reps + 1;
// ease 不变
```

**语义**：标准路径。前 6 次走固定阶梯 `1→3→7→15→30→60`，第 7 次起
`interval *= ease`（ease 初值 2.35，所以 60×2.35 = 141 天）。这是真正的
「艾宾浩斯式」前段 + 「SM-2 式」后段。

### EASY（轻松，ordinal 3）

```java
double interval = reps <= 0 ? 3.0
                : reps < 6  ? LADDER[reps] * 1.35
                :            max(3.0, (ease + 0.3) * prev);
double ease = min(3.2, prevEase + 0.15);
repetitions = reps + 1;
```

**语义**：秒答。跳过一级阶梯（×1.35），难度因子 +0.15。
新卡直接给 3 天（因为「轻松」说明已经会了）。

## 3. 收尾 clamp

```java
long minDue = now + 60_000;
if (result.dueAt < minDue) result = result.withDueAt(minDue);
```

保证任何评级都不会让卡片在「1 分钟内」再次到期，避免同一轮复习里死循环。

### ⚠️ `ease` 是「软边界」，不是硬约束

这是我在不变量扫描里发现的真实行为差异（`validation.txt`）：

| 输入 ease | AGAIN | GOOD | EASY |
|---|---|---|---|
| 1.0（低于下限） | → **1.30**（被 `max` 收回） | → **1.00**（原样透传） | → 1.15 |
| 4.0（高于上限） | → 3.80 | → **4.00**（原样透传） | → **3.20**（被 `min` 收回） |

原因：`GOOD` 分支根本不修改 `ease`；`AGAIN` 只有下限 `max(1.3, …)`，
没有上限；`EASY` 只有上限 `min(3.2, …)`，没有下限。

**实际影响**：数据库 `ease_factor REAL NOT NULL DEFAULT 2.35`，正常流程下
四分支的净效果是 `ease ∈ [1.3, 3.2]`；只有外部直接写入越界值（改库/导入）
才会让 `GOOD` 把越界值一直带下去。重写版**保留了这个行为**（不做额外 sanitation），
以保证与原版逐位一致。

## 4. 间隔 → 中文标签（`b4.v.i0`）

| 条件 | 输出 | 备注 |
|---|---|---|
| `d < 1/24` | `round(d*1440)` 分钟，最少 1 | |
| `d < 1` | `round(d*24)` 小时，最少 1 | |
| `1 ≤ d < 30` | `round(d)` 天，最少 1 | |
| `30 ≤ d < 365`，`d/30 < 2` | **固定「1 个月」** | 易错点：30 天显示成「1 个月」 |
| `30 ≤ d < 365`，`d/30 ≥ 2` | `"%.1f 个月"` | |
| `d ≥ 365` | `"%.1f 年"` | |

**坑**：`round` 是四舍五入，不是截断。`3.6 天` 显示「4 天」，`29.5 天` 显示「30 天」。
如果按 `toInt()` 截断，`29.999` 会显示「29 天」而原版显示「1 个月」。
重写版用 `kotlin.math.roundToInt()` 对齐。

## 5. 示例数据的时间分布（`z2.a` 的 seed）

理解这个有助于看懂首页截图：

| 卡片序号 | due_at 偏移 | interval_days | repetitions | lapses |
|---|---|---|---|---|
| 0–11 | `-i*1 分钟`（已过期，进今日队列） | 每 4 张一轮：`7 / 0 / 0 / 3` | `2 / 0 / 0 / 1` | 7 和 10 号卡 = 2 |
| 12–15 | `+1..4 天` | 同上 | 同上 | 0 |
| 16–19 | `+3..7 天` | 同上 | 同上 | 0 |

- 前 12 张**故意过期**，所以首次打开「今日」页就有 12 张到期卡；
- 第 7、10 张 `lapses=2`，用来演示「难卡」区域；
- 每 3 张里有 1 张 `last_reviewed_at = now - 3 天`，用来让保持率曲线有形状。

### 6.3 与原 Kotlin 的等价性说明

Kotlin 重写版（`EbbinghausScheduler.kt`）与上面的 Python oracle **逐句对应**：
同样的分支顺序、同样的 `coerceAtLeast/coerceAtMost`、同样的 `roundToInt`。
因为本机没有 Kotlin 编译器，等价性是「人工逐句核对 + oracle 向量对齐」，
不是自动化差分测试。如果你有 Kotlin 环境，可以照 `scheduler-vectors.txt`
写一个 JUnit 参数化测试来做机器验证。

## 7. 与原版 SM-2 的差异

| 项 | 标准 SM-2 | 本 APP |
|---|---|---|
| 评级 | 0–5 六级 | 4 级（重来/困难/记住/轻松） |
| 难度因子 | `EF' = EF + (0.1 - (5-q)*(0.08+(5-q)*0.02))` | 固定步长 ±0.15 / −0.2 |
| EF 范围 | 下限 1.3 | `[1.3, 3.2]` |
| 前 6 次间隔 | `I(n) = I(n-1) * EF` | **固定阶梯** `[1,3,7,15,30,60]` |
| lapse 后 | 保留部分 interval | 归零 + 1 分钟后重来 |
| 无「困难」档 | — | 有，×1.2 不推进阶梯 |

**结论**：它是「艾宾浩斯阶梯 + SM-2 简化评分」的混合体，设计目标明显是
**可预测的每日负荷**（固定阶梯让前 6 次负荷可控），而不是最大化记忆效率。
